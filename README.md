# GrowLab

GrowLab e una piattaforma locale per homelab dedicata alla gestione di piante, zone di coltivazione, sensori IoT, luci, immagini, firmware ESP32 e dati storici su TimescaleDB.

Il progetto nasce per girare in LAN/VPN, con servizi separati per applicazione, database e monitoring. L'obiettivo non e creare una piattaforma cloud generica, ma un sistema controllabile, ispezionabile e sicuro per un homelab reale.

## Stato del progetto

MVP locale avanzato.

Sono presenti:

- monorepo applicativo;
- backend Go + Gin;
- worker Go MQTT;
- frontend Next.js App Router;
- contratto OpenAPI;
- client TypeScript generato con Orval;
- database PostgreSQL/TimescaleDB con migrazioni goose;
- query generate con sqlc;
- firmware ESP32 PlatformIO;
- upload immagini e firmware su filesystem/volumi Docker;
- dashboard web con grafici, light mode, dark mode e system mode;
- integrazione monitoring esterna per homelab;
- script backup/restore e baseline sicurezza.

Restano volutamente non attivi:

- autenticazione;
- irrigazione reale;
- automazioni pompa;
- AI;
- rules engine operativo;
- kiosk mode;
- monitoring VM/Proxmox;
- export avanzati.

## Moduli principali

### Dashboard

- vista operativa su stato API, alert, zone, device, eventi e firmware;
- grafici dashboard con Recharts;
- dark/light/system mode;
- polling frontend con TanStack Query.

### Piante e zone

- CRUD piante e zone;
- profili target per zona;
- storico salute pianta manuale;
- eventi pianta;
- checklist manuali;
- timeline con immagini e metadata di crescita;
- Plant Wiki base.

### Device e sensori

- device ESP32 registrati;
- heartbeat e last seen;
- capability model;
- sensor calibration;
- ingestion MQTT di telemetry, heartbeat, status e OTA status.

### Lighting

- integrazione Shelly Dimmer 2 via HTTP locale;
- comandi on/off/brightness;
- profili lighting;
- eventi lighting persistiti.

### Firmware e OTA

- upload firmware su volume dedicato;
- canali `dev`, `beta`, `stable`;
- OTA job metadata;
- OTA dry-run;
- worker predisposto per status OTA;
- nessun update automatico forzato dal backend.

### Irrigazione

Il modulo irrigazione e solo predisposto.

- feature flag disabilitati di default;
- API safety status;
- UI read-only;
- `manual-run` restituisce sempre `IRRIGATION_DISABLED`;
- nessun comando pompa;
- nessun publish MQTT di irrigazione.

### AI

AI/Ollama e futura.

- `GROWLAB_FEATURE_AI=false` di default;
- `growlab-ollama` e dietro Compose profile `ai`;
- Ollama non espone porte host;
- nessun endpoint API AI;
- nessuna UI AI;
- nessuna automazione AI.

## Prerequisiti

- Go
- pnpm
- Docker + Docker Compose plugin
- PostgreSQL/TimescaleDB esterno su `pg-01`
- goose
- sqlc
- Node.js compatibile con Next.js
- PlatformIO per firmware ESP32

Il Makefile prova anche a trovare `goose` e `sqlc` installati con `go install` in `$HOME/go/bin`.

## Configurazione

1. Copiare l'env example:

```bash
cp .env.example .env
```

2. Impostare almeno:

```env
GROWLAB_DB_HOST=pg-01
GROWLAB_DB_PORT=5432
GROWLAB_DB_NAME=growlab
GROWLAB_DB_USER=growlab
GROWLAB_DB_PASSWORD=change-me
GROWLAB_DB_SSLMODE=require

GROWLAB_LAN_BIND=127.0.0.1
GROWLAB_CORS_ORIGINS=http://localhost:3000
```

3. Mantenere disabilitati i moduli non progettati:

```env
GROWLAB_FEATURE_AUTH=false
GROWLAB_FEATURE_AI=false
GROWLAB_FEATURE_IRRIGATION_MANUAL=false
GROWLAB_FEATURE_IRRIGATION_AUTOMATION=false
```

## Comandi utili

```bash
make sqlc
make openapi-generate
make docker-config
make security-check
```

Comandi database:

```bash
make migrate-up
make migrate-down
```

Attenzione: `make migrate-up` applica modifiche al database configurato. Usarlo solo quando `.env` punta al database corretto.

Comandi sviluppo:

```bash
make dev-web
make dev-api
make dev-worker
```

I comandi pesanti sono intenzionalmente manuali:

```bash
go test ./...

pnpm build
make build

```

## Deploy app

La compose applicativa e in:

```text
infrastructure/docker/docker-compose.yml
```

Validazione:

```bash
make docker-config
make security-check
```

Avvio manuale:

```bash
docker compose -f infrastructure/docker/docker-compose.yml up -d
```

Il database principale non e containerizzato in questa compose: deve vivere esternamente su `pg-01`.

## Backup e restore

Backup:

```bash
make backup
```

Restore:

```bash
GROWLAB_RESTORE_CONFIRM=restore bash infrastructure/scripts/growlab_restore.sh /path/to/backup
```

Il backup include dump PostgreSQL, volumi immagini/firmware, configurazione Docker GrowLab, `.env` locali se presenti e bundle Git.

La repo homelab monitoring viene salvata separatamente.

## Guardrail di sicurezza

- Nessuna autenticazione nel MVP: usare solo LAN/VPN.
- Non esporre servizi GrowLab su internet.
- Redis e Ollama non pubblicano porte host.
- MQTT e dashboard EMQX devono restare su LAN/VPN.
- CORS deve puntare solo agli origin reali.
- `.env` e backup vanno trattati come segreti.
- Irrigazione e AI restano disabilitate.
