# GrowLab

GrowLab is a local-first homelab platform for managing plants, growing zones, IoT sensors, lighting, images, ESP32 firmware, and historical data on TimescaleDB.

The project is built to run on a LAN/VPN, with separate services for the application, database, and monitoring. The goal is not to build a generic cloud platform, but a controllable, inspectable, and secure system for a real homelab.

## Project status

Advanced local MVP.

Currently in place:

- application monorepo
- Go + Gin backend
- Go MQTT worker
- Next.js App Router frontend
- OpenAPI contract
- TypeScript client generated with Orval
- PostgreSQL/TimescaleDB database with goose migrations
- queries generated with sqlc
- ESP32 PlatformIO firmware
- image and firmware upload to filesystem/Docker volumes
- web dashboard with charts and light/dark/system modes
- external homelab monitoring integration
- backup/restore scripts and a security baseline

Intentionally not yet active:

- authentication
- real irrigation
- pump automation
- AI
- an operational rules engine
- kiosk mode
- VM/Proxmox monitoring
- advanced exports

## Main modules

### Dashboard

- operational view of API status, alerts, zones, devices, events, and firmware
- dashboard charts with Recharts
- dark/light/system mode
- frontend polling with TanStack Query

### Plants and zones

- CRUD for plants and zones
- per-zone target profiles
- manual plant health history
- plant events
- manual checklists
- growth timeline with images and metadata
- basic Plant Wiki

### Devices and sensors

- registered ESP32 devices
- heartbeat and last-seen tracking
- capability model
- sensor calibration
- MQTT ingestion of telemetry, heartbeat, status, and OTA status

### Lighting

- Shelly Dimmer 2 integration over local HTTP
- on/off/brightness commands
- lighting profiles
- persisted lighting events

### Firmware and OTA

- firmware upload to a dedicated volume
- `dev`, `beta`, and `stable` channels
- OTA job metadata
- OTA dry-run
- worker prepared for OTA status
- no automatic updates forced by the backend

### Irrigation

The irrigation module is scaffolded only.

- feature flags disabled by default
- safety status API
- read-only UI
- `manual-run` always returns `IRRIGATION_DISABLED`
- no pump commands
- no irrigation MQTT publishing

### AI

AI/Ollama is a future feature.

- `GROWLAB_FEATURE_AI=false` by default
- `growlab-ollama` sits behind the Compose `ai` profile
- Ollama does not expose host ports
- no AI API endpoints
- no AI UI
- no AI automation

## Prerequisites

- Go
- pnpm
- Docker + Docker Compose plugin
- external PostgreSQL/TimescaleDB on `pg-01`
- goose
- sqlc
- a Node.js version compatible with Next.js
- PlatformIO for ESP32 firmware

The Makefile also tries to locate `goose` and `sqlc` installed via `go install` in `$HOME/go/bin`.

## Configuration

1. Copy the env example:

```
cp .env.example .env
```

2. Set at least:

```
GROWLAB_DB_HOST=pg-01
GROWLAB_DB_PORT=5432
GROWLAB_DB_NAME=growlab
GROWLAB_DB_USER=growlab
GROWLAB_DB_PASSWORD=change-me
GROWLAB_DB_SSLMODE=require

GROWLAB_LAN_BIND=127.0.0.1
GROWLAB_CORS_ORIGINS=http://localhost:3000
```

3. Keep the unfinished modules disabled:

```
GROWLAB_FEATURE_AUTH=false
GROWLAB_FEATURE_AI=false
GROWLAB_FEATURE_IRRIGATION_MANUAL=false
GROWLAB_FEATURE_IRRIGATION_AUTOMATION=false
```

## App deploy

The application Compose file lives at:

```
infrastructure/docker/docker-compose.yml
```

Validation:

```
make docker-config
make security-check
```

Manual start:

```
docker compose -f infrastructure/docker/docker-compose.yml up -d
```

The primary database is not containerized in this Compose file: it must live externally on `pg-01`.

## Backup and restore

Backup:

```
make backup
```

Restore:

```
GROWLAB_RESTORE_CONFIRM=restore bash infrastructure/scripts/growlab_restore.sh /path/to/backup
```

The backup includes the PostgreSQL dump, the image/firmware volumes, the GrowLab Docker configuration, local `.env` files if present, and a Git bundle.

The homelab monitoring repo is backed up separately.

See:

- [docs/BACKUP_RESTORE.md](docs/BACKUP_RESTORE.md)

## Security guardrails

- No authentication in the MVP: use LAN/VPN only.
- Do not expose GrowLab services to the internet.
- Redis and Ollama do not publish host ports.
- The MQTT broker and the EMQX dashboard must stay on LAN/VPN.
- CORS must point only to real origins.
- Treat `.env` files and backups as secrets.
- Keep irrigation and AI disabled.
